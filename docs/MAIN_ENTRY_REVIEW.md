## 原因

`73470c0` 将最新实验源码纳入同一仓库，但未重写旧 `main.py` 的抓取控制流程。最近成功实录走 `feedback_runner.py`。旧主入口默认 YAML 仍为 `yolov8s-world.pt`、0.1 阈值、单一 `cube` 提示；YAML 覆盖了 dataclass 的 v2 / 0.02 默认值。日常物体场景也没有自动切换目标类别。

另外，“未检测到可抓取目标”同时覆盖无 YOLO 框、SAM 无掩码等不同情况，容易误认为全部是 YOLO 漏检；交互改类别还会自动添加空字符串提示。

## 同图复测

使用保存的真实 Isaac Sim 图像，YOLO 推理尺寸均为 1280，未启动机械臂运动。

| 同一张腕部方块图 | 检测结果 |
|---|---|
| v1 + `cube` + conf=0.1 | 无框 |
| v2 + `cube` + conf=0.02 | 1 个 cube，置信度 0.0385 |
| v2 + red/green/blue cube + conf=0.02 | 红块 0.4091，另有弱 blue cube 候选 0.0294 |

该样本是 `yolo_cube_red_20261028_1/001_wrist.png`。完整 3 张图、4 种配置的原始结果见 [离线记录](evidence/main_entry_review_20261028/replay.json)。这些是少量诊断样本，没有形成精确率/召回率评测。其他观察视角仍有漏检，错误类别提示和低阈值也产生了误识别；不能声称已经解决模型的泛化问题。

## 本次改动

- 默认 YAML 与 dataclass 统一为 v2、0.02、1280、明确的三色方块提示；SAM 默认 vit_b。
- `main.py --classes` 显式选择当前场景目标，`--confidence` 可调整检测阈值。
- 默认配置文件定位到仓库目录，与运行时 cwd 无关；显式缺失配置直接报错。
- 支持运行时权重环境变量，打印最终模型路径与配置。
- `--observe-only` 不创建机械臂控制器，不调用运动服务；`--once` 只观察时仅等待 RGB，不要求 TF 或深度。
- 区分 YOLO 无框、SAM 无掩码；观察模式输出框数、掩码数、类别、置信度及保存的原图/结果图。
- 交互类别更新去掉空背景提示；单次执行失败返回非零退出码。

## 验证

39 项单元检查通过，新增 5 项覆盖实际默认 YAML、任意 cwd、场景类别覆盖、缺失配置、权重环境变量和空类别回归。

另外，在控制容器中用独立 ROS Domain 91 和独立 RGB 话题发布上述保存图像，实际构造 `EnhancedDetectorNode(observe_only=True, interactive=False)` 并走其 `run(once=True)`：控制器保持 None，未提供 TF/深度或运动服务，检测到 2 个框，红块生成有效 SAM 掩码，返回成功。记录见 [ROS 入口日志](evidence/main_entry_review_20261028/main-smoke.log)。这是实际主入口的图像回放检查，未重跑实时仿真抓放。

## 尚未迁移到旧主入口的部分

`main.py` 的抓取路径仍使用静态相机内参、不同步的最新 RGB-D 缓存和旧两阶段动作；第二阶段的等待也不等于新鲜帧屏障。它没有近期反馈入口的目标锁定、提起/放置验证、独立评分和异常恢复。推荐先用只观察模式诊断检测，完整闭环任务使用 README 的 `scripts/arm.sh` 入口。
